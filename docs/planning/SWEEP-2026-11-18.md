# Nine screens at 393 and 375 - dead space, clipped headers, overflow

Measured on the live build at 393x860 and 375x812, signed in as the founder, fifteen views
each, with a real browser. Three checks per view:

1. **Clip** - the distance from the app bar's bottom edge to the first child of the view. A
   negative number means the bar covers the first element.
2. **Dead** - the space between the last element's bottom edge and the bottom of the scroll
   container, counted only when the view does not scroll. A view that scrolls has no dead
   space by definition.
3. **Overflow** - elements whose box crosses the viewport edge, excluding anything inside a
   horizontal scroll container, because that is what the container is for.

## Result: 30 measurements, 2 flagged, 0 defects

| View | Clip | Dead | Overflow | Verdict |
|---|---|---|---|---|
| brief, radar, scores, rates, gaps, tracker, twin, account, copilot, learning, negotiation, trajectory, pulse, plan | 0 or more | 0 | 0 | Clean at both widths |
| searches | 0 | 233 at 393, 185 at 375 | 0 | An empty state, not a fault |

**Searches** is the only view with space below its content, and it is an empty state that
carries an instruction: "No searches watched yet. Set filters on The Radar, then press Watch
this search." A short page is not a layout fault (D-1.8), and padding it out to fill the
screen would be decoration.

## Two false positives worth recording

- **Gaps reported 33 overflowing elements** at both widths. They are the cells of a
  seven-column table inside `.tscroll`, which is `overflow-x:auto` with a 640px minimum
  table width. The table is meant to scroll sideways on a phone; the page does not.
- **Copilot reported 8.** They are the chips inside the chip rail, which is also a horizontal
  scroller. The page itself does not scroll: `scrollW == clientW` at both widths.

The probe now skips any element with a scrolling ancestor, so the number it prints is the
number that matters.

## What was not changed

Nothing. Every screen already passes, so this is a verification record, not a fix.
